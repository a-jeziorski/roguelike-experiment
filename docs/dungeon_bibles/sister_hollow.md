# The Sister Hollow — Dungeon Bible

*Brief by design, the ninth of a short run of small dungeons exercising
`tools/procgen/` against real, shipped content, one per algorithm, per
`docs/region_bibles/dust_reach.md`'s plan.*

## What it is

A single-level dungeon (`data/dungeons/sister_hollow/levels/level_01.lvl`,
45x30) generated by `tools/procgen/cellular_automata.py`: random noise
smoothed by four passes of the classic 4-5 rule into rounded, organic cave
shapes, then reduced to its largest connected component. This is the
first algorithm in this run with a direct precedent already shipped in
this project - it formalizes the exact technique originally applied by
hand for Silversilk Caves' own levels 03-05 (`docs/content_design_process.md`
§0ae: "random noise, several wall/floor smoothing passes, largest-
connected-component extraction") into reusable code (see
`docs/procgen_algorithms.md`'s cellular automata section).

**Era**: Natural, no era or faction - the same category `rootfall_hollow`
and `silver_mountain_caves` belong to. Explicitly *not* the same cave
system as Silversilk Caves - a separate, smaller cave shaped by the same
kind of slow natural process, further west on Dust Reach rather than in
the mountains proper.

## Roster

None. Zero entities, zero items - the point of this pass is exercising
the generator and the content pipeline, not a combat encounter (unlike
Silversilk Caves' own deeper levels, which do have a monster roster -
this one's deliberately left empty, matching every other test dungeon in
this run).

## Layout notes

- The generated grid is framed with `tools.procgen.base.frame_border`
  after generation, then `keep_largest_component`/`farthest_pair` are
  recomputed on the framed result - `generate()` already applies
  `keep_largest_component` internally (unlike most other generators in
  this library, which leave that to the caller) as part of the
  technique's own three-step definition, but framing can still disconnect
  a sliver right at the edge, so it's worth reapplying afterward for
  safety.
- `player_start` and the single terminal `stairs_down` sit at the two
  floor tiles `tools.procgen.base.farthest_pair` found furthest apart (by
  8-directional graph distance) within the final connected component.
- No `next_level` - reaching the stairs leaves the dungeon and returns
  directly to Dust Reach, matching this run's other terminal single-level
  dungeons.

## Tone notes

- Keep this genuinely unrelated to Silversilk Caves beyond the shared
  natural-formation technique - no shared inhabitants, no lore connection
  beyond "the same kind of place." If a future pass wants to actually
  link the two, that's a deliberate decision, not something this document
  already assumes.
