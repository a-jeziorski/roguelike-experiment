# The Fallen Colonnade — Dungeon Bible

*Brief by design - this is the first of a short run of small dungeons
built specifically to exercise `tools/procgen/`'s generator library
against real, shipped content, one per algorithm, per
`docs/region_bibles/dust_reach.md`'s explicit plan. Still gets a named
identity and an era placement per `docs/world_history.md`'s authoring
convention, but doesn't carry the narrative weight a story-driven dungeon
would.*

## What it is

A single-level Old Kingdom hall (`data/dungeons/fallen_colonnade/levels/level_01.lvl`,
45x30) generated by `tools/procgen/wave_function_collapse.py`'s default
tileset: an even scatter of single-tile wall pillars across open floor,
with the hard constraint that no two pillars ever touch (see
`docs/procgen_algorithms.md`'s wave function collapse section for the
generator itself). That constraint *is* the set piece - a regular grid of
standing supports, never merged into a solid wall, is exactly what reads
as built architecture rather than a cave the cellular-automata or
drunkard's-walk algorithms would produce instead.

**Era**: Old Kingdom, now fallen. Unlike Broken Watch or The Windrest (also
fallen Old Kingdom sites), nothing has moved into this one - it sits far
enough out on Dust Reach, genuinely unclaimed frontier per that region's
own bible, that no present-day faction has found it yet. Empty, not
defended and not squatted.

## Roster

None. Zero entities, zero items - deliberately minimal, since the point of
this pass is exercising the generator and the content pipeline (loader
validation, overworld stitching, world-history placement), not a combat
encounter. A future pass is free to populate it if it wants a real reason
for a player to visit beyond curiosity.

## Layout notes

- The generated grid is framed with `tools.procgen.base.frame_border`
  before anything else - `wave_function_collapse`'s default tileset has
  no concept of an edge, so its raw output otherwise leaves floor sitting
  right at the map's array boundary, which reads as an unenclosed level
  rather than a real hall.
- `player_start` and the single terminal `stairs_down` are placed at the
  two floor tiles `tools.procgen.base.farthest_pair` found furthest apart
  (by 8-directional graph distance) within the level's largest connected
  component (computed *after* framing, so neither ever lands on the
  border) - the same entry/exit placement discipline every other
  procgen-sourced level in this project uses.
- No `next_level` - reaching the stairs leaves the dungeon and returns
  directly to Dust Reach, the same terminal-stairway pattern
  `sunless_hollow`'s single level uses.
- The pillars are purely a navigation/line-of-sight texture (see
  `content/schema.py`'s `TILE_PASSABILITY` - `wall` blocks movement and
  sight identically wherever it appears); there's no vault, switch, or
  other mechanic attached to any specific pillar.

## Tone notes

- Don't retroactively assign this a faction or defender without a real
  reason - "unclaimed" is the point, not a placeholder waiting to be
  filled in.
- If a later pass wants to give Dust Reach's first dungeon actual stakes,
  that's a deliberate follow-up decision, not something this document
  half-commits to.
